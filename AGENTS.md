## Workflow rules (important — apply every time)

1. **Edit only in `web/`.** Never edit `web-shareable/` directly — it's regenerated by the sync script and any local change there will be wiped.
2. **Test locally first.** Use `python3 app.py`, `./run.sh`, or `npm run dev` and verify on `http://localhost:3000`. Confirm the production build is green with `npm run build`.
3. **Ask before pushing.** Always confirm with the user before:
   - `git push` (any branch, especially `main`)
   - `vercel`, `vercel --prod`, `npx vercel`, `npx vercel --prod`, or any equivalent deploy
   This rule supersedes the general "ask once then proceed" pattern. Re-confirm every time, even if a previous push in the same session was authorised. The reason: the user wants to save tokens by verifying changes in the local environment before consuming them on remote build/deploy iterations.
4. **Sync before sharing.** When the user wants to hand a clean copy to a reviewer, run:
   ```bash
   bash scripts/sync-shareable.sh
   ```
   That refreshes `../web-shareable/` from the current state of `web/`.

## Quick reference

| Action | Command |
|---|---|
| Local dev | `python3 app.py` (or `npm run dev`) |

| Deploy preview to Vercel (ASK FIRST) | `npx vercel` |
| Deploy production to Vercel (ASK FIRST) | `npx vercel --prod` |
